Persistent Latent Affective Architecture (PLAA)
Emotion-Conditioned State Dynamics for Continuous Character Simulation
Figure 1 — System Overview
Figure 1. Overview of the Persistent Latent Affective Architecture (PLAA). A personality state vector S_t ∈ ℝd is initialized from a character card via Persona Encoder φ and flows top-to-bottom through the system each turn. Memory retrieval is affect-conditioned: S_t drives what is recalled from episodic, semantic, and user-model stores. The GRU-style State Transition f_θ updates S_t from retrieved memory M_t, user context C_t, and user model U. A logarithmic Affective Decay mechanism prevents runaway emotional accumulation — extreme states are pulled back toward baseline without erasing the memory's trace. The updated state S_{t+1} is fed back persistently (dashed loop, right). The Emotion Projector π maps S_{t+1} to a sequence memory tensor e_mem, injected into the Language Decoder via a repurposed Emotion Cross-Attention layer (original Audio Gate preserved as emotion gate g ∈ (0,1)). State and memory are serialized as character.soul for cross-session identity continuity.
