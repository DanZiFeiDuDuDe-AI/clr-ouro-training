# 复现与环境

## 先识别实验版本

本仓库是一组研究工作区的归档，不是已统一打包的 Python 应用。CLR / PLAA 早期版本使用 Qwen 系列模型；LoopLM 与后续 rebase 使用 Ouro。不同阶段的数据协议、状态初始化、训练目标和环境不同，不能共用一份随意升级的环境来宣称复现。

开始任何运行前，应核对对应目录中的 config、checkpoint hash、数据清单、原始报告及当前授权范围。历史脚本的存在不代表允许启动下游阶段。

## 当前 O3-REBASE2 记录的运行环境

- 训练端记录：Linux，PyTorch 2.9.0，设备名 `BW`。
- 归档脚本所用 DTK 路径：`/opt/dtk-26.04/hip/lib`、`/opt/dtk-26.04/lib`、`/opt/dtk-26.04/.hyhal/rocm_smi/lib`。
- 诊断脚本：[diagnose.py](../research/looplm/clr_o3_rebase2_vgen2_failure_localization/diagnose.py)。
- 顺序执行及逐训练下载：[run_diagnostics.py](../research/looplm/clr_o3_rebase2_vgen2_failure_localization/run_diagnostics.py)。
- 独立的原始报告及环境记录见对应实验目录，不应将这些设置推广到所有历史阶段。

文件清单校验仅使用 Python 标准库；分卷解压需要 `zstandard`。SSH 传输工具另需 `paramiko`；下载 Release 附件使用 GitHub CLI。可通过 `requirements-archive.txt` 安装工具依赖。恢复文件不会执行模型代码，也不会调用 `torch.load`。

## 数据和权重

先运行 `python tools/restore_artifacts.py`，再检查目标阶段的相对路径。保留旧绝对路径的脚本需要显式配置模型、cache 和输出目录；不要将不同来源的同形状权重互相替代。

原始实验清单中的哈希用于追踪当时文件；本次发布若因凭据脱敏而改变了脚本或文本，应使用 `manifests/files.jsonl` 中的发布哈希，并参考 `redactions.json`，不能把旧清单悄悄改成新哈希。

历史源码的语法和编码检查记录在 `manifests/source_syntax_audit.json`。少量历史文件存在检查异常，归档保留原始内容，不借整理文件改写研究实现。归档维护脚本中含作者原工作区路径；使用者恢复资料只需根目录 `tools/restore_artifacts.py` 和 `tools/verify_archive.py`。

## 训练完成后的下载约定

当前项目约定：每次远程训练完成，包括 diagnostic probe，都关闭训练连接后重新连接服务器，拉取 checkpoint、config 和 metrics，校验 SHA-256 并保留 transfer manifest。权重仍只在远端时，不应宣称实验已完整交付。

公开副本不包含密码和 DPAPI 凭据。`tools/remote_weights.py` 通过运行者自行提供的 `LOOPLM_SSH_PASSWORD` 环境变量或其本机受保护配置连接；历史脚本中的硬编码密码已替换。不能依赖作者旧电脑的认证信息来运行。
