# 数据、权重与恢复

## 文件在哪里

代码、论文、配置和报告随 Git 仓库提供。模型权重、adapter、NumPy 特征缓存、数据打包文件及少量大型文本文件保存在 `archive-2026-10-20` Release 的分卷中。

- [下载入口](https://github.com/DanZiFeiDuDuDe-AI/clr-ouro-training/releases/tag/archive-2026-10-20)
- [分卷、对象与路径映射](../manifests/artifacts.json)
- [全部来源路径清单](../manifests/files.jsonl)
- [实际归档统计](../manifests/archive_summary.json)

分卷属于同一个连续的 tar.zst 流，不应单独解压某一个分卷。使用 Zstandard 压缩；同一 SHA-256 的内容只保存一份，恢复时会放回清单中的全部相对路径。

## 一键恢复

要求 Python 3.11+ 和 GitHub CLI。公开 Release 可直接下载；若 GitHub API 要求认证，先执行 `gh auth login`。

```bash
python -m pip install zstandard
python tools/restore_artifacts.py
```

脚本将分卷下载到 `.archive-cache/`，以流式方式验证分卷与对象的 SHA-256，每个对象通过校验后才恢复到正式路径，全部分卷和对象都通过才报告成功。下载缓存、恢复后的多份来源目录和临时对象都占磁盘空间；总需求以索引中的分卷大小、唯一对象大小和逻辑文件大小为准，应按逻辑路径副本预留空间。

如果目标文件已存在且 SHA-256 一致，会保留；内容不同则停止，不覆盖用户文件。下载中断后可以再次运行，已完成并通过校验的分卷可以复用。

## 离线验证与恢复

将全部分卷放入某个目录后：

```bash
python tools/restore_artifacts.py --cache /path/to/parts --offline --verify-only
python tools/restore_artifacts.py --cache /path/to/parts --offline --output /path/to/restored
```

`--verify-only` 校验所有对象，不恢复权重。只有源文件哈希和对象哈希都通过，才能把模型产物视为完整。

## 数据使用范围

训练/validation/TestA/TestB 数据文件作为历史实验输入一起保存。下载和恢复不代表允许将 TestA/TestB 用于调参。不得将某次单组件 validation gate 通过解释为整条 O3 集成路径已通过。
